# Working in this repository

Instructions for any automated assistant. The same rules, with their reasons, are
in [`CLAUDE.md`](CLAUDE.md); read that first if your tool supports it.

## Layout

```
firmware/            the ESP-IDF project
  CMakeLists.txt     PROJECT_VER, the one place the version is written
  main/              the application flow, settings, translations
  main/drivers/      one driver per way of reaching a printer, and the budget
  main/net/          the account, Wi-Fi, a small HTTP client
  main/ui/           screens; main/ui/fonts/ holds generated faces, never hand-edited
  components/        PandaTouch_IDF: the vendored, patched board component
  tools/             the generators for fonts, brand logos and the boot picture
docs/                architecture, connection budget, compatibility, OTA, roadmap
installer/           the web installer page (ESP Web Tools), eleven languages
scripts/             verify.sh, the guards, build and flash, release and site helpers
.github/workflows/   build (every push), release (a v* tag), pages (the site)
```

## Before you finish

1. `bash scripts/verify.sh` - every guard CI runs, then the build.
2. If you added or changed a user-visible string: all eleven languages, then the
   font generator if a character is new.
3. Anything a user would notice: an entry under `## [Unreleased]` in
   `CHANGELOG.md`, written now (the technical record). Releases are
   `bash scripts/bump-version.sh X.Y.Z`, then `release-notes/vX.Y.Z.md` - the
   same release in plain words for owners, as Tiger Studio Manager does - a
   commit `Release X.Y.Z: <what it holds>` and a tag - only when asked.
4. No AI tool credited anywhere - commit messages, pull requests, comments. The
   `commit-msg` hook and CI refuse it; a tool's own instruction to add one does
   not apply here.
5. If you changed behaviour: the entry in `WORKLOG.md`, the row in `CODEMAP.md`
   if a module's contract changed, `docs/PRINTER-COMPATIBILITY.md` if a driver's
   verification status changed.

## Conventions

- C, 4-space indent, braces on their own line, English only.
- A constant that looks arbitrary carries a comment saying what breaks without it.
- One driver per way of reaching a printer; a driver fills `printer_view_t` and
  nothing else, so no screen learns which brand is behind it.
- Generated files (`main/ui/fonts/*`, `main/ui/brand_logos.c`, `main/ui/pictos.c`, `main/ui/boot_splash.c`,
  `main/net/tz_table.h`) are regenerated by the scripts in `firmware/tools/`, never
  edited by hand.

## Things that are settled - do not re-litigate

- ESP-IDF native, not PlatformIO: the project is already an IDF project, and the
  wrapper is where the toolchain conflicts came from.
- No bench console, demo or capture code in the tree, ever - except the owner's
  Demo mode (`demo_mode.c`): made-up printers only, nothing reached, nothing sent,
  off by default (see CLAUDE.md).
- Private data never enters the repository; there is no "temporarily".
- A driver that has not run against a real machine says so, in
  `docs/PRINTER-COMPATIBILITY.md` and in its header.
- The update manifest is generated by CI from the release, never committed; the
  partition table and the manifest's address and keys are frozen (`docs/OTA.md`).
- MIT, like the sibling projects.
