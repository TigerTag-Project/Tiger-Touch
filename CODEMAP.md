# Code map

**The [Landmines](#landmines) table is this file.** Everything above it is the
short list of module facts that `ls` and `grep` do not give you; everything a
grep would have told you has been left out. No line numbers are recorded: nothing
verifies them, and a number nothing verifies is a number that lies. Grep for the
symbol.

Build, hardware and rule facts are in [CLAUDE.md](CLAUDE.md).

## Modules worth a note

| File | What is not obvious |
|---|---|
| `ui/ui_onboard.c` | The setup's pages, after TigerScale's: a question with *Later* (`ui_show_prompt`), the same as a panel from the right on LVGL's **top layer** (`ui_show_side_prompt`, closed by `new_page()` before any other screen), the sign-in page, the pairing page with its QR (`lv_qrcode`, `CONFIG_LV_USE_QRCODE`). |
| `main/main.c` | The application task owns the whole flow (boot picture, Wi-Fi, account, printer list, dashboard, settings pages) and is a state machine over `wait_event()`. `feed_task` is separate: once a second it takes the selected printer's view from `links` and pushes it to the dashboard under the LVGL lock, and it also calls `cloud_keepalive()`, because a TLS renewal needs a stack the LVGL task does not have. `presence_task` writes the device's heartbeat to the account (`cloud_heartbeat()`, `users/{uid}/tigertouches/{mac}`) on core 0, every 30 s or 5 min asleep, at once when the printers on or answering change. |
| `drivers/links.c` | Keeps one open connection per *enabled* printer and one `printer_view_t` per connection, in PSRAM. Opens at most one per tick (a TLS handshake is a memory spike). The budget is in **load slots**, 1 slot = 1 KB of internal RAM; a printer that fits is on, one that does not is refused with a message. "Load slot", never plain "slot" - a slot is a spool tray everywhere else. |
| `drivers/drivers.c`, `drivers/printer_driver.h` | The registry. A driver answers `support()` for an account printer, and `drivers_for()` returns the first match **by brand**: two drivers can share a brand (Elegoo's CC2 and CC1) as long as their `support()` are disjoint. |
| `demo_mode.c` | *Settings > Demo mode*, the owner's exception to "no fake printer" (CLAUDE.md): when on (setting `demo`, read once, a switch restarts), `main.c` replaces the account's printers with ten made-up ones, `drivers_for()` hands every printer to `DRIVER_DEMO`, `links.c` switches them all on without saving the owner's choice, and nothing reaches the network or a printer. The driver moves the progress (1 % / 20 s), wobbles the temperatures, draws filament colours from Tiger Studio's palette at each start, and answers pause, resume, stop and the light on the picture only. |
| `net/addr.h` | A printer's address as the account gives it, `host` or `host:port`: `addr_with_port()` keeps a written port and adds the brand's otherwise, `addr_host_only()` drops it (Elegoo CC1's UDP discovery). Every LAN driver builds its URI through it; nothing else splits an address by hand. |
| `net/cloud.c` | TigerTag account over Firebase REST: sign-in (password, or `cloud_pair_*`: pairStart / pairPoll, then `signInWithCustomToken`, the account id decoded from the ID token's `user_id`), token refresh, printers read from Firestore, the language written back (`cloud_push_lang`). The password is used for one request and never kept; the refresh token is. `cloud_link()` is what the account icon shows. Renewals are serialised by a mutex because the feed task and the application task both reach it. |
| `net/tz.c`, `net/tz_table.h` | The zone comes from a country: the account's, else the access point's, else UTC. `tz_table.h` is generated (`firmware/tools/make_tz_table.py`), never edited; to change a country's zone, change PRIMARY in the generator. The device keeps UTC and only the printer card's estimated end is local time. The country is never logged, only which source answered. |
| `net/ota.c` | Reads `version.json` (GitHub Pages) and installs the image it names into the other slot. Nothing is switched until the whole image hashes to the manifest's SHA-256, names itself `tiger_touch` and carries the announced version. The download and the flash writes run in a task with an **internal-RAM** stack (a flash write disables the cache, and a PSRAM stack is unreachable then); buffers and mbedTLS stay in PSRAM. A new image is on probation: `main.c` starts a 60 s `esp_timer` whose callback calls `ota_mark_healthy()`; a reset before then and the bootloader rolls back. The background check (`ota_watch_task`) only reads; installing is always a touch on the update page. |
| `main/settings.c` | The NVS wrapper (one namespace). `settings_factory_reset()` erases the **whole** partition, Wi-Fi driver records included; the next boot is a first boot. |
| `main/i18n.c`, `main/i18n_table.h` | An X-macro table, eleven columns, English fallback. `lang` is the device's language; its absence is what makes a device "new" (with no Wi-Fi and no account). A language picked here sets `lang_push` until it is written to the account; without one pending, the account's language is applied at start. A 1.x `lang_a` is migrated once. |
| `ui_kit_header()`, `ui_kit_scroll_list()`, `ui_kit_scroll_rail()` | The shared TigerScale grammar every list page is built from (settings, Wi-Fi list). A new list page uses them rather than its own header or list, so the devices keep one look. |
| `ui/ui_settings.c` menu | TigerScale's settings list: `settings_row()` (icon box, label, value, chevron), `draw_icon()` (shapes, not glyphs, for user / globe / sun / printer), `scroll_rail()` (PRESSED, two rows a press, greyed at the ends). The values come from `main.c` in a `settings_menu_t`; the scroll position is kept in `s_menu_scroll` until the menu is left for home. |
| `ui/ui_setup.c`, `ui_settings.c`, `ui_dashboard.c` | Screens never decide anything: they draw a state and post events. The dashboard is built once and kept; a language change deletes and rebuilds it (`ui_language_changed`). |
| `ui/ui_job.c` | Pause / resume and stop, one pair per card and one on the full view, built here so they behave alike; stop opens a confirmation modal (`open_stop_modal`, a child of the screen on show, keeping the row index, never a pointer into the card) and only its red button posts `stop`; and the light button beside them: all three always drawn, dimmed and inert when they cannot act (`ui_job_set`: a job runs and `can_control`; `can_light`) (`PV_CTL_LIGHT_ON/OFF` go through the same `links_control()` path; a driver sets `can_light` and `light_on` from its report). Pause is a touch. They post `EV_PRINTER_JOB`; the application task calls `links_control()`, which calls the driver's optional `control`. Shown only when the view says `can_control` and a job runs: a driver sets it from `online`, and the Bambu driver only on the local broker. |
| `ui/ui_cards.c` | The printers page: a sideways-scrolling row of one card per switched-on printer, or, in the list view (`ui_cards_set_list`, the header's view button, setting `home_view`), a vertical column of light rows that keep the light, pause and stop buttons, in the settings' column and rail (`ui_kit_scroll_list` / `ui_kit_scroll_rail`). `main.c`'s `refresh_cards()` gives every card its view once a second (a view is copied under the links lock, drawn under the LVGL lock, never both). The cards are in PSRAM (`calloc` per page) and forgotten by `new_page()`, like every pointer to a widget of a screen that goes. Touching one posts `EV_PRINTER_PICK`; its job buttons post `EV_PRINTER_JOB` (see `ui/ui_job.c`). The nozzle tiles re-lay out when the printer's nozzle count changes; the chamber is "--" at 0. |
| `ui/ui_tile.c`, `ui/pictos.c` | The temperature tile of both screens: a pictogram (nozzle, bed, chamber) and its value, centred together by a flex row; a caption over the value only where the layout asks (two nozzles). `pictos.c` is generated from `tools/pictos.json` (`tools/make_pictos.py`): 24 px masks for the tiles, 16 px for the captions of file / time left / end. A new pictogram is drawn in a browser from its SVG in `tools/pictos/`, not by hand. |
| `ui/ui_wifi.c` | The Wi-Fi wave and the account icon, kept current by one LVGL timer. Persistent widgets (the dashboard's) and transient ones (a page's) are registered separately. |
| `drivers/drv_klipper.c` | Any Klipper printer through Moonraker over HTTP (not Snapmaker, which has its own). Lists the objects once (`detect()`), then asks exactly those each poll; a 4xx re-runs the detection (Klippy restarted). Port 7125 when `ip` has none; `X-Api-Key` only when the account has one. Time left from the file's `estimated_time`. |
| `drivers/drv_octoprint.c` | OctoPrint over HTTP with `X-Api-Key`; port 80 when `ip` has none. `/api/printer` answers 409 when no printer is plugged into OctoPrint: shown as such, not as offline. No light, no layers, no filament. |
| `drivers/drv_anycubic.c` | LAN: a client per printer. Cloud: one session for the account (`s_as`), signed in as the slicer does, verified against Anycubic's CA with SHA-1 allowed (`acu_tls_hook`). The broker closes the whole session on a subscription or a publish it does not allow: subscribe per family, send only the two `getInfo`, no command - every cloud printer goes down with one bad publish. One session per account and client type: it signs in as "android" and moves on when kicked. |
| `drivers/drv_bambu.c` | Cloud and LAN share the report parser. Reports are partial: a block can arrive without the `ams` unit data, so the AMS state is merged, never rebuilt. `mc_percent` includes the preparation phase. |
| `drivers/drv_elegoo_sdcp.c` | The Centauri Carbon 1. Needs the printer's MainboardID, from the account or from one UDP question, asked without blocking. Its pause (129), resume (131) and stop (130) come from the OpenCentauri API notes, which Tiger Studio itself flags as not confirmed on a CC1. |
| `drivers/driver_util.h`, `ws_rx.c`, `mqtt_rx.c` | What every driver does with a report, once: reading a number or a string out of JSON, turning a maker's colour string into `0xRRGGBB`, and putting a chunked WebSocket or MQTT message back together. A fix to one of these is a fix to all of them; a driver that needs a variation writes its own and says why. |
| `ui/fonts/`, `ui/brand_logos.c`, `ui/pictos.c`, `ui/boot_splash.c` | Generated; see `firmware/tools/`. |

## Landmines

| Where | What goes wrong | Why |
|---|---|---|
| Any widget pointer held by a timer | A crash (`LoadProhibited`) on a language change, intermittently | The dashboard is deleted and rebuilt; a timer still held the old widget and asked LVGL if it was valid, which reads freed memory. Forget pointers *before* the delete, untested. |
| Label buffers (`pv_nozzle_t.label`, notices) | A word loses its last letters, or its number | UTF-8: two bytes a Cyrillic letter, three a Chinese character. Size for the longest language. |
| Writing the whole flash image at 0x0 | The Wi-Fi and the account are gone | The image spans the NVS. Write parts at their offsets. |
| Flashing above 115200 baud | "Corrupt data" half-way, or a board that boots into noise | The CH340K bridge loses bytes at 230400 and above on some hosts. |
| `lv_obj_t` use outside `PT_LVGL_SCOPE_LOCK` | Rare, unreproducible corruption | LVGL is not re-entrant. |
| Holding `links_lock()` across a network request | Every printer link and the home screen's cards stand still for as long as the request (12 s for the account) | Read into a copy and lock only to swap it in, as `fetch_printers()` does. |
| Opening several TLS links at once | Out of internal RAM; handshakes fail | The budget exists for this; do not raise a price without measuring it. |
| Bambu cloud presence | "Online" for about a minute after the printer is switched off | The cloud does not announce an extinction; the driver waits out its window. |
| K2 first connection | One disconnect, then it reconnects by itself ~5 s later | Seen on the first WebSocket handshake; the reconnect is the library's. |
| A job command | Nothing happens and nothing says so | A printer that refuses a command (a Bambu in cloud mode, a Prusa job id not known yet, a CC1 whose command numbers are unconfirmed) never reports it. The buttons are drawn only where the connection takes commands (`printer_view_t.can_control`), and a driver that has not run against its machine says so in its header. |
| `partitions.csv`, `OTA_MANIFEST_URL`, the manifest's three keys | Units in the field stranded on their version | None of them can be changed over the air: the device cannot rewrite its table, and an old unit reads that address and those keys forever. `docs/OTA.md`. |
| `esp_ota_*` from a task whose stack is in PSRAM | A crash during an update, half-way through the slot | The flash write turns the cache off; keep it in `ota.c`'s own task. |
| The setup's reminder panel | A panel left over a screen that is not the home | It lives on LVGL's top layer, above every screen; `new_page()` closes it, and the home loop closes it before Settings and the printer menu. A new way to show a screen that does not go through `new_page()` must close it too. |
| `cloud_pair_poll()` approved | "Failed" after the phone said yes | The custom token is handed out once: a failed exchange spends the pairing. Start again; never retry the exchange. |
| `settings_factory_reset()` | Everything is gone, on purpose | The confirmation screen is the only guard; do not call it from anywhere else. |
